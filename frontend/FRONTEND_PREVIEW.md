# Original application browser demo

Set `VITE_PREVIEW_MODE=true` before `npm run build`. AppEntry loads the original App directly for both normal and demo builds. The customer/admin layouts, product cards, cart, checkout, payment, tracking and admin pages are reused, with a visible DEMO MODE badge and "Demo mode — no real payments or orders are processed." notice. FrontendPreview.tsx is only a compatibility export and is not selected as the website entry. Production output remains `frontend/dist`.

The existing approved snapshot supplies all 37 products and 69 explicit priced variants, preserving the approved prices/availability, including the Avocado Sandwich and Aalu Cheese Burger overrides. Source-menu descriptions and featured flags are retained where available. Dragon, Beetroot and ABC remain source-menu entries pending database restoration; this build does not restore anything to a database. The saved menu is not a statement of live stock. The 28 original Unsplash photos referenced by menuImages/Home are bundled in `public/demo-menu` (approximately 3.6 MB); no replacement product photos were invented. Products without mappings retain the original emoji fallback.

Network service calls are replaced by `demoFetch`, an in-process adapter with no network fallback. Demo builds alias the API origin to empty and replace external checkout with a rejecting stub; menu SSE and tracking use local events instead. The preview-only CSP prohibits network API connections, frames and form submissions. No real QR, merchant details, transaction references, provider scripts or auth requests are supplied. Browser tests watch native network API invocations, not just successful requests. Do not add analytics, external scripts or service workers.

Demo cart, checkout/idempotency keys and tracking tokens use a `fr-demo:` prefix. Browser-local menu/settings/admin state and at most 50 orders are saved under `fr-demo:state:v1`; original cart/customer keys are not read, overwritten or cleared. Use sample names only. Phone numbers are not saved to demo orders; no data leaves the browser. Anyone can enter the explicitly labeled admin demo without a username or password, see only that browser's local data and change simulated order status. Same-origin tabs receive storage events; different browsers/devices do not share orders. Demo Paid is not verified revenue. Cancellation creates no refund obligation. Reset demo clears only the demo namespace. Storage failure refuses writes rather than falling back to a server.

Demo tracking/payment access now resolves exclusively from the shared local demo-order store, even in a fresh tab without sessionStorage keys. Existing a0b2347 demo orders remain compatible; no data reset or new credential is required. Production tracking still uses only its original per-tab sessionStorage token. The Demo Admin navigation uses React Router Link, preserving client routing instead of requesting a new `/admin` document.

Live diagnosis (2026-11-21): the existing Static Site served `/` and `/index.html` with HTTP 200, but direct `/admin` and `/order/...` returned HTTP 404. The code fix cannot configure Render. Separately approve/apply the documented `/*` -> `/index.html` Rewrite (not Redirect) before claiming direct links/refresh work publicly. Local production tests use a static server with SPA fallback; they do not prove the current Render rewrite is fixed. Do not deploy or change hosting settings under code-only approval.

Limits: image upload and real payment verification/refund recording are unavailable; existing table/report placeholder pages remain placeholders. Opening-hours editing is illustrative; the demo uses its local accepting-orders switch, not the production scheduling engine. This demo is not production authorization or proof of actual gateway/database behavior.

`VITE_PREVIEW_MODE=false` (or unset) preserves the normal application and its real service paths; demo aliases, UI overrides and CSP are absent. The original API/auth/payment implementation is retained. The flag takes precedence over the older explicit database-backed menu-preview experiment. Always rebuild when changing it.
